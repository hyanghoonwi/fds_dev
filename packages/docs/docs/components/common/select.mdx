# Select

여러 항목 중 **하나**를 고르는 드롭다운입니다. 어드민 목록의 필터("상태: 전체")와 폼의 모든 선택 입력에 씁니다. 네이티브 `<select>`가 아니라 직접 만든 listbox라서 목록의 모양과 키보드 동작이 일정하고, `searchable`을 켜면 입력해서 찾는 선택 상자가 됩니다.

[Input](./input)과 같은 필드 props(`label`, `orientation`, `labelWidth`, `required`, `description`, `error`)를 내장하고 있어서 따로 감쌀 필요가 없습니다. 규칙은 [Input의 공통 필드 props](./input#폼-컨트롤-공통-필드-props)를 보세요. 여러 개를 고르는 입력은 [CheckboxGroup](./checkbox)이고, 보기가 서너 개뿐이면 [RadioGroup](./radio-group)이 더 빠릅니다.

## Usage

`options`에 `{ value, label }` 배열을 주고, 값은 이벤트가 아니라 **문자열**로 받습니다. 아무것도 고르지 않은 상태는 `null`이고, 이때 `placeholder`가 보입니다.

export function BasicDemo() {
  const [role, setRole] = useState(null);
  return (
    <div
      style={{ width: 280, display: "flex", flexDirection: "column", gap: 8 }}
    >
      <Select
        label="역할"
        options={roleOptions}
        value={role}
        onChange={setRole}
        placeholder="역할을 선택하세요"
      />
      <span style={{ fontSize: 13, color: "var(--fds-text-secondary)" }}>
        현재 값: {String(role)}
      </span>
    </div>
  );
}

`value` 대신 `defaultValue`를 주면 상태를 컴포넌트가 가집니다(비제어). `onChange`는 **다른 옵션을 골랐을 때만** 호출되고, 이미 선택된 옵션을 다시 눌러도 호출되지 않습니다.

## 옵션과 "전체" 항목

필터의 "전체"는 값이 빈 문자열(`""`)인 **실제 옵션**입니다. `value=""`이면 placeholder가 아니라 "전체"가 선택된 것으로 보입니다. 선택 안 함은 `null`입니다.

## 폼에서 쓰기

`name`을 주면 선택한 값을 담은 숨은 `<input>`이 함께 렌더링되어 `FormData`와 네이티브 폼 제출에 그대로 들어갑니다. `null`이면 빈 문자열이 제출됩니다.

export function FormDemo() {
  const [role, setRole] = useState(null);
  const [submitted, setSubmitted] = useState(false);
  const [result, setResult] = useState("");
  return (
    <form
      style={{ width: 300, display: "flex", flexDirection: "column", gap: 12 }}
      onSubmit={(event) => {
        event.preventDefault();
        setSubmitted(true);
        if (role === null) {
          setResult("");
          return;
        }
        const data = new FormData(event.currentTarget);
        setResult(JSON.stringify(Object.fromEntries(data.entries())));
      }}
    >
      <Select
        label="역할"
        name="role"
        required
        options={roleOptions}
        value={role}
        onChange={setRole}
        placeholder="역할을 선택하세요"
        error={submitted && role === null ? "역할을 선택해 주세요." : undefined}
      />
      <Select
        label="상태"
        name="status"
        options={statusOptions}
        defaultValue=""
      />
      <Button type="submit" variant="primary">
        저장
      </Button>
      {result && (
        <pre style={{ margin: 0, fontSize: 12 }}>{"FormData: " + result}</pre>
      )}
    </form>
  );
}

## 검색 가능한 Select

`searchable`을 켜면 트리거가 텍스트 입력이 됩니다. 글자를 치면 `options`가 걸러지고 일치한 부분이 굵게 표시됩니다. 별도의 Combobox 컴포넌트가 아니라 **같은 Select의 모드**라서 라벨, 에러, 가로 배치 같은 필드 props를 그대로 씁니다.

- 닫혀 있을 때는 선택한 항목의 이름이 보입니다. 열면 그 이름이 전체 선택되어 있어서 바로 입력하면 검색어로 바뀝니다.
- 대소문자를 구분하지 않고 `label`에 검색어가 **포함**되는 항목을 보여 줍니다. 결과가 없으면 `emptyMessage`(기본 "검색 결과가 없어요")가 나옵니다.
- **입력한 글자는 값이 되지 않습니다.** 고를 수 있는 값은 항상 `options` 안의 `value`뿐입니다("유효한 ID만" 선택하게 하는 규칙).

### 서버에서 검색할 때

`onSearch`를 넘기면 컴포넌트는 직접 거르지 않고, **부모가 검색 결과로 `options`를 바꾸는 것**으로 봅니다. 검색어가 바뀔 때마다 `searchDelay`(기본 250ms)만큼 기다렸다가 한 번만 호출하므로, 빠르게 입력해도 요청은 한 번입니다. 요청 중에는 `loading`을 켜세요. 목록에 "불러오는 중…"이 나오고 `aria-busy`가 켜집니다. 메뉴를 닫으면 `onSearch("")`가 한 번 더 호출되어 목록을 처음 상태로 되돌릴 수 있습니다.

아래 데모는 600ms 걸리는 가짜 API입니다. **응답이 뒤바뀌어도 안전하도록** 마지막으로 보낸 요청의 응답만 반영합니다. `비트`나 `테스트토큰`을 입력해 보세요.

export const serverDataset = assetOptions.concat(
  Array.from({ length: 80 }, (_, i) => {
    const n = String(i + 1).padStart(3, "0");
    return {
      value: "TKN" + n,
      label: "테스트토큰 " + (i + 1) + " (TKN" + n + ")",
    };
  }),
);

export function ServerSideDemo() {
  const [assetId, setAssetId] = useState(null);
  const [results, setResults] = useState(serverDataset.slice(0, 20));
  const [loading, setLoading] = useState(false);
  const [log, setLog] = useState({ lastQuery: "", requests: 0 });
  const latest = useRef(0);

const handleSearch = (query) => {
const requestId = latest.current + 1;
latest.current = requestId;
setLoading(true);
setLog((prev) => ({ lastQuery: query, requests: prev.requests + 1 }));
setTimeout(() => {
// 더 최근 요청이 있으면 이 응답은 버린다
if (requestId !== latest.current) {
return;
}
const keyword = query.trim().toLowerCase();
setResults(
serverDataset.filter((option) => option.label.toLowerCase().includes(keyword)).slice(0, 20),
);
setLoading(false);
}, 600);
};

return (
<div style={{ width: 320, display: "flex", flexDirection: "column", gap: 12 }}>
<Select
        searchable
        label="연결 asset"
        options={results}
        value={assetId}
        onChange={setAssetId}
        onSearch={handleSearch}
        loading={loading}
        placeholder="asset 검색/선택"
        description="검색어와 맞는 최대 20개만 불러와요."
      />
<pre style={{ margin: 0, fontSize: 12 }}>
{JSON.stringify({ ...log, selected: assetId, shown: results.length }, null, 2)}
</pre>
</div>
);
}

```tsx
/>
```

### 폼에서: 값이 제출된다

검색형이어도 `name`으로 제출되는 것은 **입력한 글자나 보이는 이름이 아니라 선택한 옵션의 `value`**입니다. 아래는 서버의 ID(`place-03`)가 제출되는 예입니다. 비어 있으면 에러를 보여 줍니다.

export function SearchableFormDemo() {
  const [place, setPlace] = useState(null);
  const [error, setError] = useState(undefined);
  const [submitted, setSubmitted] = useState("");
  return (
    <form
      noValidate
      style={{ width: 320, display: "flex", flexDirection: "column", gap: 12 }}
      onSubmit={(event) => {
        event.preventDefault();
        const data = new FormData(event.currentTarget);
        if (!data.get("place")) {
          setError("장소를 선택해 주세요.");
          setSubmitted("");
          return;
        }
        setError(undefined);
        setSubmitted(
          JSON.stringify(Object.fromEntries(data.entries()), null, 2),
        );
      }}
    >
      <Select
        searchable
        name="place"
        label="장소"
        required
        options={placeOptions}
        value={place}
        onChange={(next) => {
          setPlace(next);
          setError(undefined);
        }}
        placeholder="등록된 장소 검색"
        error={error}
      />
      <Button type="submit" variant="primary">
        저장
      </Button>
      <pre style={{ margin: 0, fontSize: 12 }}>
        {submitted || "제출 결과가 여기에 보여요"}
      </pre>
    </form>
  );
}

## 키보드

DOM 포커스는 항상 트리거(버튼 또는 입력창)에 있고, 활성 항목은 `aria-activedescendant`로 알려 줍니다.

### 일반 모드

| 키                      | 동작                                                                                     |
| ----------------------- | ---------------------------------------------------------------------------------------- |
| `Enter` `Space` `↓` `↑` | 목록 열기 (`↓`는 선택된 항목, 없으면 첫 항목이 활성)                                     |
| `↓` `↑`                 | 다음/이전 항목으로 이동 (끝에서 멈춤, 비활성 항목은 건너뜀)                              |
| `Home` `End`            | **목록이 열려 있을 때** 처음/끝 항목으로 이동                                            |
| `Enter` `Space`         | 활성 항목 선택 후 닫기                                                                   |
| 글자 입력               | 타입어헤드: 입력한 글자로 시작하는 항목으로 이동 (600ms 안에 이어 치면 여러 글자로 찾음) |
| `Esc`                   | 닫기 (포커스는 트리거에 남음)                                                            |
| `Tab`                   | **선택하지 않고** 닫고 다음으로 이동                                                     |

### 검색 모드 (`searchable`)

| 키                              | 동작                                                                             |
| ------------------------------- | -------------------------------------------------------------------------------- |
| 글자 입력                       | 목록 열기 + 검색어 입력, 첫 번째 일치 항목이 활성                                |
| `↓` `↑`                         | 열기, 열려 있으면 항목 이동                                                      |
| `Home` `End`                    | **목록이 열려 있을 때만** 처음/끝 항목으로 이동 (닫혀 있으면 입력창의 커서 이동) |
| `Enter`                         | 활성 항목 선택. 활성 항목이 없으면 아무것도 하지 않음                            |
| `Space`                         | 공백 입력 (선택하지 않음)                                                        |
| `Esc`                           | 닫고, 입력하던 검색어를 버린 뒤 선택된 항목의 이름으로 되돌림                    |
| `Tab` / 포커스 이동 / 바깥 클릭 | 선택하지 않고 닫고, 검색어를 버리고 이름으로 되돌림                              |

한글처럼 조합 중인 글자의 `Enter`와 방향키는 글자 확정에 쓰이므로 무시합니다.

## 접근성

- 일반 모드의 트리거는 `<button role="combobox">`이고, 검색 모드는 `<input role="combobox" aria-autocomplete="list">`와 보조 토글 버튼입니다. 둘 다 `aria-expanded`, `aria-controls`, `aria-activedescendant`를 가지고, 목록은 `role="listbox"`, 항목은 `role="option"`(`aria-selected`, `aria-disabled`)입니다.
- `label`의 `htmlFor`는 트리거(검색 모드에서는 입력창)를 가리켜서, 라벨을 눌러도 포커스가 갑니다.
- 에러가 있으면 `aria-invalid`가 켜지고 메시지는 `aria-describedby`로 연결됩니다. `required`는 `aria-required`로 전달됩니다.
- 로딩 중에는 목록에 `aria-busy`가 붙습니다.
- 검색 모드의 일치 강조는 글자 모양만 바꾸고 텍스트는 그대로라서, 스크린 리더는 이름을 한 번에 읽습니다.

## 참고

- 목록은 [Popover](./popover) 위에 그려지고 `document.body` 포털을 쓰지 않습니다. 그래서 `overflow: hidden`인 조상 안에서는 목록이 잘릴 수 있고, 화면 가장자리에 닿았을 때 위치를 뒤집는 처리도 없습니다.
- `Modal` 안에서도 열립니다. `Esc`는 목록을 먼저 닫고, 한 번 더 누르면 모달이 닫힙니다.
- **한글 입력**: 검색 모드에서는 조합 중인 `Enter`·방향키를 무시하므로 한글로 찾아도 안전합니다. 다만 일반 모드의 타입어헤드는 `event.key`로 글자를 읽어서, 한글 IME로 조합 중에는 이동하지 않을 수 있습니다. 한글로 찾아야 하는 긴 목록은 `searchable`을 쓰세요.
- 검색 모드에서 메뉴가 열린 채 입력창이 포커스를 잃으면(다른 곳을 누르거나 `Tab`) 메뉴가 닫히고 검색어는 버려집니다.
- `ref` 타입이 `HTMLButtonElement | HTMLInputElement`로 넓습니다. `HTMLButtonElement`로만 선언한 콜백 ref는 타입 에러가 날 수 있으니, 필요하면 두 타입을 모두 받도록 선언하세요.
- 여러 개를 고르는 `MultiSelect`는 아직 없습니다. 개수가 적으면 [CheckboxGroup](./checkbox)을 쓰세요.
